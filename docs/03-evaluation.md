# 效果验证

阶段 2 已实现业务工具与 SQLite 草稿存储。32 项领域/工具测试通过；命令为 `node --import tsx --test --test-reporter=spec tests/domain.test.ts tests/tools.test.ts`，实际输出见 [阶段 2 测试记录](../examples/test-results/phase-02.txt)。Agent 与真实模型整体验证在后续阶段进行。

覆盖正常保存、缺资料、规则证据、冲突建议待确认、精确授权、防伪造、同 ID 不同输入、防重复、跨连接唯一约束、保存故障、规则/占用变化、无可用时段和部分成功。发现并修复过一个问题：重复保存已确认草稿时，传入不同建议时间可能返回原草稿；现在明确拒绝重新排期，回归测试保留。

另修复时间精度问题：所有输入时间最多允许毫秒精度，避免高精度字符串被 JavaScript Date 截断后误判为相同时间，绕过硬性时间确认或请求指纹。

质量复核进一步修复两项状态问题：工具返回的草稿回执与权威账本隔离，外部修改回执不能改变确认状态；保存实时校验成功后清除过期的“无可用时段”标记，避免报告与持久化回执矛盾。

## 验证方法

1. 使用 Node 测试运行器验证真实业务函数、数据库事务、幂等、冲突与确认边界。
2. 使用离线模型替身验证完整执行链和故障注入，记录为 `mock`。
3. 配置真实模型后，固定合成资料，运行正常、冲突、资料不足、规则风险与保存失败场景；保留原始动作和工具结果。
4. 改变占用时段再运行，核对模型后续动作和最终状态。
5. 所有输出保存于 `examples/`，本文件随实际结果更新并链接证据。
