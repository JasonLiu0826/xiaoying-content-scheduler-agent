# 需求与验收标准

## 用户、目标与范围

用户是内容运营人员。输入素材 ID、渠道、带时区的发布时间要求、请求 ID，以及可选的人工确认信息。读取合成素材与审核规则，查询已有排期，输出每项素材的审核状态、风险原因、建议时段、待确认项与草稿保存状态。

本项目选择题 1。运行方式为 CLI；所有资料为合成数据，所有写操作仅保存本地草稿，不提供发布工具。单次请求可包含多个素材，各项独立记录结果，不能因部分成功而宣称全部完成。

## 硬性边界

- 模型选择工具、观察结果后决定补查、替代时段、请求确认或阻断。离线 Mock 仅验证执行流程。
- 硬性时间不可未经用户同意变更。替代建议可以保存为 `pending_confirmation` 草稿，但不能占用该替代时段或称为已确认。
- 人工同意来自 CLI 输入文件中的确认列表，模型工具参数不能伪造授权。确认绑定素材 ID、渠道、原要求时间和建议时间。
- 审核阻断、缺资料或未知素材均不可保存为可确认的排期。
- 草稿按请求项幂等；同一请求重跑只返回同一草稿。相同请求 ID 换输入应明确报错。
- 已确认草稿与已有排期均占用渠道/时段；保存时重新检查冲突。待确认建议不占用时段。
- 设模型步数和工具调用次数硬上限，达到任一上限返回明确的未完成状态，保留已成功结果。

## 验收矩阵

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| A01 | 正常排期 | 审核通过、原时段可用、草稿落盘、状态准确 |
| A02 | 素材信息缺失 | 列出缺失字段，请求补充，不能虚报审核或保存成功 |
| A03 | 规则风险 | 输出规则 ID 和事实依据；阻断风险不可被模型绕过 |
| A04 | 时段冲突 | 模型查替代时段，保留原硬性要求，替代建议待确认 |
| A05 | 重复提交 | 跨进程重跑仍只有一份草稿；变更输入触发幂等冲突 |
| A06 | 保存失败 | 注入保存故障，数据库无新增，最终明确保存失败 |
| A07 | 占用时段变化 | 换占用数据后，工具结果和后续动作相应改变 |
| A08 | 资源上限 | 无限工具选择被有限步数/调用次数终止 |
| A09 | 授权边界 | 模型伪造确认、修改硬性要求、跳过审核均被工具拒绝 |

至少三组实际输入、输出与 Trace，覆盖正常、资料不足、工具失败，并覆盖上述全部验收点。至少两条真实模型路径用于评估动态决策；如未配置模型，必须明确列为未完成。
