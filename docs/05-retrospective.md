# 开发复盘

## 工程复盘（AI辅助过程记录）

最容易出错的是把“模型正常结束”混同于“业务保存成功”，以及把模型生成的确认参数当成人工授权。方案将保存、授权和最终状态交给可验证的业务层，模型负责动作选择。

已有通用 Agent 能复用模型接入经验，但大规模 Runtime 的权限、记忆和桌面集成会增加笔试项目的审查成本，因此采用独立的小型循环。

实际最难的部分是让“已保存、待确认、未完成”始终与事实一致。复核发现并通过回归测试修复了：已确认草稿被不同时间重放；亚毫秒输入被 Date 截断；返回回执引用可改变账本；保存成功后保留旧的无时段状态；Windows路径大小写/硬链接绕过输出保护。CLI 报告文件失败时，也必须保留已经保存的业务结果，不能把结果抹掉。

模型接入方面，将工具错误以结构化观察回传，允许模型选择替代时段或结束，比增加自动重试更能体现本题的动态决策。HTTP 传输重试只解决暂时网络问题，不计作模型重规划的证据。真实模型正常路径和资料不足/风险路径会调用不同数量的工具，冲突路径则根据占用选择不同时间。

## 取舍与下一步

- 优先完成可复制的 CLI、业务边界与验证；没有投入可选界面或线上部署。
- 当前审核是合成资料上的明确规则匹配，不声称覆盖真实内容审核风险；未来可增加可审查的审核服务接口与人工审核流程。
- 待确认建议不预占时段，因此确认时必须重新验证；未来如业务需要可增加带过期时间的软预留。
- 数据库存储防止重复写入，但没有实现跨进程共享完整 Agent 运行检查点；可继续补充失败步骤续跑与恢复策略。
- 真实模型固定样本的通过不能代替统计评估；下一步应扩大素材、冲突组合、异常和对抗输入数据集。
